# lagrange-point-orbit-simulator

Python three-body / Lagrange-point simulator.

## Layout
- `lagrangepointsimulator`: core physics and integration. Must not import Qt, `lagrangepointinputs`, `lagrangepointapi` or the GUI packages.
- `lagrangepointinputs`: presets and the safe expression evaluator for user input. Depends on the core, must not import Qt or `lagrangepointgui`.
- `lagrangepointapi`: what the web page needs as plain data (form spec, simulation, plot data, presets). Depends on the core and `lagrangepointinputs`, must not import Qt.
- `lagrangepointgui`: Qt Widgets desktop GUI. Depends on the core and `lagrangepointinputs`, never the reverse.

## Tooling
- Package management: `uv` (pyproject.toml, hatchling).
- Lint/format: `ruff check`, `ruff format`. Type check: `ty check`. applied to src
- Plain `requirements.txt`, `requirements-dev.txt`, `requirements-gui.txt` are generated by the export script via `uv export`.
- Distribution: PyInstaller (the `build` dependency group), CI on `ubuntu-22.04`, the oldest GitHub-hosted image, for glibc portability.

## Numerical code
- Do not assume a performance change is free. Verify with `inspect_asm()` / `inspect_llvm()`.

## Constraints
- The desktop app must keep working. Changes to the core must be backward compatible.
- Prefer FOSS dependencies. Report the license of any new dependency.
- Do not add dependencies or change the packaging without saying so.

## Working style
- If these instructions conflict with what you find in the repo, stop and ask instead of guessing.
- Keep commits small and scoped to one change.
